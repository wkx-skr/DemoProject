# 王一一：可扩展属性面板

本版把属性分为两层：**稳定性格的初始设计**和**学习过程中不断新增的动态标签**。标签名称不需要提前列出；新主题可以直接落入属性库，不必新增数据库字段或改初始配置。

它实现的是可追溯的自我描述和学习记录。记忆、反思、兴趣和自主目标可以改善行为连续性，但这些功能不能证明主观意识，也没有可据此计算的“意识觉醒分”。

## 初始属性

设计源是 [独立属性模板](../characters/wang_yiyi.attributes.json)。它没有接入原人格加载器，不会覆盖现有人格。数值是可编辑的设计选择，不是心理测量结果，也不代表越高越好。

| 属性 | 设计初值 / 100 | 表达倾向 |
| --- | ---: | --- |
| 好奇心 | 75 | 愿意问为什么、探索新主题 |
| 温暖 | 70 | 友善而具体地回应 |
| 主见 | 55 | 表达自己的理由，也接受修正 |
| 表达主动性 | 45 | 在相关话题中提出小问题或建议 |
| 耐心 | 60 | 允许慢慢尝试与纠错 |
| 开放性 | 65 | 比较不同观点和证据 |
| 计划性 | 45 | 把兴趣变成可以完成的小步骤 |
| 玩心 | 60 | 保留轻松和创作空间 |

身份、称呼、关系、已有 XP 和阶段均继承现有状态。年龄、生日、技能分数及未采集的当前状态保持未知，不用 0 代替未知。初始阅读、颜色、观察兴趣仅作设计参考；动态属性库不会凭模板凭空增加证据。

## 学习时出现新属性

例如最初没有“摄影构图”：

1. DSH 保存视频观察，并给出“摄影构图”主题及候选感想。
2. 属性库自动创建 `interest / 摄影构图`，保存来源链接、来源时间与感想。
3. 再看另一个相关视频，增加一份独立依据；反复采样原视频不会增加依据数。
4. 后来改变看法，同一来源的新解释更新当前证据，并保留旧版本历史。
5. 聚合后的候选标签通过现有同步队列进入 LivingMemory，供相关聊天召回。

`candidate` 表示暂时的解释，不表示必须逐条等待用户批准。新标签可以自动创建、保存和召回；它仍可被后续证据修正，不能据此直接宣布掌握了一项技能。

| 类别 | 标签示例（仅说明） | 自动记录的含义 |
| --- | --- | --- |
| `interest` | 摄影构图、古典音乐 | 候选兴趣或不偏好倾向 |
| `knowledge_topic` | 三分构图法 | 接触过这个知识主题，尚不等于核实或掌握 |
| `skill` | 分析一张照片的构图 | 候选能力；熟练度需要实际作品或任务评估 |
| `question` | 为什么逆光会形成轮廓？ | 还想进一步探索的问题 |

类别用于约束更新方式，**类别内的标签名称完全开放**。不同写法只做 Unicode、大小写和空白规范化；不自动断言语义相近的两个词就是同一属性，避免错误合并。新建一种更新规则或数据类型仍需扩展代码，不允许网络文本自行增加执行权限。

## 每个标签保存什么

| 数据 | 用途 |
| --- | --- |
| 属性 ID、类型、名称 | 稳定识别一个开放标签 |
| 状态 | 当前自动生成记录均为候选 |
| 独立证据数 | 同一视频/网页证据键只算一次；不等于独立作者或已核实来源数量 |
| 偏好 / 不偏好 / 未定计数 | 显示支持与反例，避免只累加正面意见 |
| 来源 URL、来源类型、观察时间 | 返回原资料并区分新旧 |
| 最新简短感想 | 概括暂时的看法，不保存隐含推理或把自述当事实 |
| 可选自评 | 提议分数、量表范围与方法；不是经过验证的能力分 |
| 版本历史 | 查看同一标签的证据如何被修正 |

“已保存 10 次”不等于“90% 喜欢”，也不等于“已经精通”。本版不根据计数自动产生置信概率、智力分、技能等级或意识值。属性与关系、权限、私聊共同 XP 分开管理。

## 已接通的路径

```text
DSH 的观察与候选感想
   → 按明确主题转换学习事件
   → 独立属性 SQLite：新标签、独立依据、变化历史
   → 生成本地属性面板 HTML 快照
   → 聚合候选标签 → 现有同步队列 → LivingMemory 详情核验
```

DSH 观察正文不会因为新增标签元数据而重新导入。聚合标签有自己的稳定标识；内容变化时追加新的云端历史版本。检索到多个版本时应依据来源时间理解它们，不能把旧版本叠加成额外证据。旧云端版本不会被本工具自动删除。

沿用 `livingmemory:global`、`default` 人格和已配置适配器；使用相同人格与适配器的全局聊天可以召回。当前标签为该人格共享的学习资料，WYY 的共同活动 XP 仍按原私聊范围计算。

在抖音同步配置增加：

```json
"attributes": {
  "enabled": true,
  "state_db": "%USERPROFILE%/.dsh/douyin-browser/control/yiyi-attributes.sqlite3",
  "panel_path": "attribute-panel.html"
}
```

这是现有配置的一个字段；完整格式见 [同步配置示例](../integrations/douyin/config.example.json)。属性数据库必须独立于 DSH 源库和同步队列。相对路径按配置文件所在目录解析。

每次现有同步任务运行，都会读取新增主题、刷新本地面板并同步候选标签。面板是文件快照，不是自动联网的网页；文件刷新后需重新打开或刷新浏览器。本机需开机、登录、联网并满足原计划任务的电源条件。

同步报告新增 `attribute_count` 和 `attribute_observations_changed`，配置面板时另有 `panel_status`。面板生成失败会单独报告并使本轮状态为 `partial`，云端同步仍继续。`plan` 仍只预览原始 DSH 来源，不建立属性库，也不预估已有属性库的全部聚合记录。云端失败时本地标签可能已经保存；是否已上传以同步队列和回执为准。

## 网页学习与后续来源

网页学习采用同一种事件格式，本版提供事件接入口；**目前自动采集器只接了现有 DSH 抖音记录**。网页阅读器或研究 Agent 需要把实际读到的资料转换为这些事件，不能把一个尚未访问的链接称为已经学习。

```json
[
  {
    "kind": "interest",
    "label": "摄影构图",
    "source_id": "web:example:composition",
    "evidence_key": "web:example:composition",
    "source_url": "https://example.com/composition",
    "observed_at": 1700000000000,
    "summary": "演示事件：想继续比较主体居中和偏置的视觉效果。",
    "stance": "like",
    "source_type": "web"
  }
]
```

这是虚构格式示例，不能作为生产学习证据。`observed_at` 是来源观察的 Unix 毫秒时间；`source_id` 标识来源事件，`evidence_key` 标识同一独立作品/页面，重复采样保持不变。同一时间却有冲突内容的更新不能任意覆盖，采集器应给出真实的修订时间。

可选 `assessment` 格式为 `{"value": 40, "scale_min": 0, "scale_max": 100, "method": "模型提议的自评方法"}`；展示时保留“未验证”标记。没有自评时省略该字段。

在项目目录使用本地命令：

```powershell
python -X utf8 -m yiyi_attributes --db runtime/attributes-demo.sqlite3 observe --events runtime/learning-events.json
python -X utf8 -m yiyi_attributes --db runtime/attributes-demo.sqlite3 list
python -X utf8 -m yiyi_attributes --db runtime/attributes-demo.sqlite3 history ATTRIBUTE_ID
python -X utf8 -m yiyi_attributes --db runtime/attributes-demo.sqlite3 panel --out runtime/attributes-demo.html
```

上面使用独立演示库；生产接入时指定同步配置中的属性数据库，并保持人格 ID 一致。`observe` 只写本机属性库，下次抖音同步启用属性模块时，会将该库中的聚合候选一起传到云端。命令没有浏览器抓取、任意执行代码、自动重写人格或训练模型的功能。

## 现有案例与取舍

核对日期：2026-11-11（Asia/Shanghai）。以下是可借鉴机制，后面的接入选择属于本项目设计，不表示这些项目已装在服务器。

| 案例 | 已展示的机制 | 对一一的启发 |
| --- | --- | --- |
| [Generative Agents（2023）](https://arxiv.org/abs/2304.03442) | 25 个模拟角色以记忆、反思和计划形成连续行为 | 从事件形成带依据的总结，再提出后续活动 |
| [Voyager（2023）](https://voyager.minedojo.org/) | Minecraft 自动课程、可复用技能库及环境反馈；不依赖模型权重微调 | “学会”需要执行与结果反馈，保存可重复使用的方法 |
| [Letta / MemGPT 的记忆设计](https://docs.letta.com/v1-sdk/concepts/stateful-agents) | 持续状态、可编辑和共享的记忆块 | 区分身份、自我描述和外部证据；本项目继续使用已有 LivingMemory |
| [Anthropic 的内省研究（2025）](https://www.anthropic.com/research/introspection) | 在受控实验中观察到有限、不稳定的内部状态报告能力；作者明确不据此判断主观意识 | 不把一段自述或“我觉得自己成长了”当成验证结果 |

可逐步增加的下一层是：提出一个小目标 → 实际执行 → 用新任务评估结果 → 更新带证据的技能记录。当前完成的是开放标签、来源、变化历史和记忆接入；自主任务调度与技能评估器尚未启用。
